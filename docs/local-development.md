# СОБЕРИ

Демонстрационный фронтенд для подготовки мероприятий. React, TypeScript, Vite. Без сервера, регистрации, платежей и внешних API. Все данные и изменения хранятся в браузере.

## Запуск

```powershell
npm install
npm run dev
```

Откройте http://localhost:5173. Для повторного запуска установка не нужна.

## Проверки

```powershell
npm run build
npm test
npm run test:model
```

Браузерные тесты используют установленный Google Chrome. Путь к нему задан в `playwright.config.ts`.

## Обучение

При первом посещении приложение предлагает семь коротких шагов или сразу начать работу. Постоянная кнопка «Обучение» рядом с заголовком повторно запускает знакомство. Подсветка показывает выбор мероприятия, Антипровал, назначение исполнителя, статус, ожидаемые расходы, перестановку блоков и тему.

Ознакомительные шаги имеют кнопку «Далее». Практические ждут реального сохранения исполнителя/статуса либо изменения порядка блоков. Есть «Назад», «Пропустить», управление клавиатурой и выход через Escape. Недоступная цель даёт возможность повторить показ или явно пропустить шаг.

Учебное мероприятие и его расположение существуют только в памяти отдельно от пользовательских данных. После выхода возвращаются прежнее мероприятие, раздел, режим настройки, прокрутка и фокус. Обновление страницы закрывает учебную сессию. Прогресс запуска, завершение, отказ и пропуск хранятся отдельно в `soberi-onboarding-v1`, поэтому обучение не запускается заново автоматически. Выбор темы сохраняется обычным образом.

## Сценарий демонстрации

1. Обзор: 8 из 10 задач выполнено, отдельно видны две критические проблемы.
2. Назначьте помощника на проверку оборудования. Предупреждение об отсутствии ответственного исчезнет, но прогресс останется 8 из 10. Выполнение отмечается отдельно.
3. Откройте проблему с помещением. После получения брони выберите «Выполнено» и сохраните: проблема закроется, прогресс станет 9 из 10.
4. Задачи можно добавлять и редактировать: название, описание, статус, ответственный, срок и критичность. Для помещения задаётся контрольная дата. Доступны фильтры по статусу и ответственному; удаление требует подтверждения.
5. Бюджет: оплачено 8 000 ₽, осталось обязательств 9 000 ₽, ожидается ещё 5 000 ₽. Итого 22 000 ₽ при лимите 20 000 ₽. «Отметить оплату» переносит сумму из обязательств в оплачено, сохраняя итог. План учитывается отдельно. Пустые суммы означают неизвестную стоимость, ноль — известное отсутствие расходов.
6. В задачах план разделён на этапы. Добавляйте, переименовывайте, сворачивайте и перемещайте этапы; переносите задачи за ручки либо кнопками «Выше» / «Ниже» и списком «В этап». Порядок не меняет сроки, исполнителей и зависимости. Удаление этапа требует подтверждения с количеством задач и предупреждением о критических задачах.
7. «Сохранить как шаблон» сохраняет структуру, команду и плановые статьи. При создании мероприятия выберите свой шаблон и новую дату: сроки пересчитаются относительно неё, идентификаторы будут новыми, выполнение, подтверждения, обязательства и фактические оплаты сбросятся. Источник сохранится. Доступны также встроенный «Мастер-класс» и пустой план. Прошедшие рекомендованные сроки явно отмечаются и не сдвигаются автоматически.
8. В обзоре «Настроить экран» включает отдельный режим: меняйте порядок и ширину блоков, скрывайте необязательные и возвращайте через список. На телефоне всегда одна колонка. «Готово» завершает настройку. Сброс расположения требует подтверждения и не меняет данные мероприятий. Индикатор критических проблем в шапке остаётся даже при скрытом «Антипровале»; нажатие возвращает блок.
9. «Восстановить пример» с подтверждением вернёт исходные этапы, задачи, команду и бюджет примера, сохранив другие мероприятия, шаблоны и первоначальную дату примера.

Дата примера устанавливается через три дня после первого открытия и сохраняется. Для чистой записи видео используйте отдельное приватное окно или сценарий `scripts/open-recording.mjs`; пользовательское хранилище очищать не нужно.

Оригинальные изображения логотипа из вложений сохранены в `public/brand/*-original.png`. Из исходной графики выделены прозрачный знак и отдельное начертание названия, без перестановки частей и перерисовки. Основной синий #003AFD измерен по наиболее частому насыщенному синему пикселю исходного знака; метаданные — `public/brand/source.json`. В ночной теме цвет знака сохраняется, меняется только цвет названия. Один фоновый знак имеет прозрачность 4%, обрезается границами экрана и не перехватывает нажатия.

В шапке доступны светлая, тёмная и системная темы. Выбор хранится отдельно от данных мероприятия в `soberi-theme`. Скрипт `public/theme-init.js` применяет его до загрузки React и стилей. Системный режим реагирует на изменение настройки ОС; выбор синхронизируется между вкладками. Если localStorage недоступен, переключатель продолжает работать в текущей вкладке.

«Антипровал» рассчитывает пять условий: отсутствие подтверждения помещения с контрольной даты, отсутствие ответственного у открытой критической задачи, просроченную критическую задачу, превышение бюджета и неизвестную оценку обязательной статьи. Действия открывают связанную задачу или расход. Прогресс подготовки отделён от этих условий.

Общее состояние находится в `App.tsx`, правила и расчёты — в `data.ts`. Данные записываются в прежний ключ `soberi-demo-v1`, версия схемы — 3. Прежние мероприятия мигрируют с сохранением статусов, назначений, сроков и сумм; задачи распределяются по этапам. Для прежних статей, где отдельного плана ещё не было, начальный план переносится из их прежнего ожидаемого итога и доступен для уточнения. Назначения хранятся по идентификаторам участников команды мероприятия. Все вычисления денег выполняются в копейках.

Расположение рабочего пространства общее для пользователя и хранится отдельно в `soberi-workspace-v1`; его правила — в `workspace.ts`. Настройка блоков не меняет порядок задач и не отключает проверки. Для обоих конструкторов используется одна библиотека `@dnd-kit/core`: перенос начинается только за ручку, показывается место вставки, Escape отменяет действие. Кнопки порядка и выбор этапа работают без перетаскивания.

Визуальная проверка: `node scripts/responsive-check.mjs`. Скриншоты широкого экрана, ноутбука, телефона и модальных окон сохраняются в `artifacts/responsive`.

Проверка двух тем: `node scripts/theme-check.mjs`. Снимки всех трёх разделов, форм события, задачи и расходов, оплаты, команды и подтверждения восстановления на компьютере, ноутбуке и телефоне, а также измерения контраста сохраняются в `artifacts/themes`.

Проверка конструкторов: `node scripts/builders-check.mjs`. Обе темы, ширины 320–1920 пикселей, все блоки в одну и две колонки, новые формы и подтверждения. Снимки и отчёт об ошибках/переполнении — `artifacts/builders`.

Проверка обучения: `node scripts/learning-check.mjs`. Все семь шагов и практические формы на четырёх размерах экрана в обеих темах; 80 снимков и отчёт о границах подсказок/перекрытии форм — `artifacts/learning`.

Финальная проверка: [сценарии, исправления и ограничения](final-review.md). Дополнительные снимки всех разделов после знакомства и перетаскивания: `node scripts/final-visual-check.mjs`, результаты — `artifacts/final`. Окно для записи без изменения пользовательского профиля: `node scripts/open-recording.mjs` (при работающем dev-сервере).

Перед восстановлением старого/повреждённого состояния исходная строка резервируется в `soberi-demo-recovery-v1`. Непригодные шаблоны не сбрасывают мероприятия. Если резервирование невозможно, автосохранение не затирает исходник. Копия сохраняется и при последующем обновлении страницы; это последняя резервируемая версия, а не история изменений.
